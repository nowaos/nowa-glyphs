# Category audit

Routine for reviewing one `src/apps/scalable/_<category>/` folder: what to delete,
what to rename and — the most common finding — what is fine but has no link.

Usage: "run the audit on `_<category>` following audit.md".

---

## 1. Inventory — what exists and what has links

```bash
CAT=_media   # adjust
for f in src/apps/scalable/$CAT/*.svg; do
  n=$(basename "$f" .svg)
  if [ -d "links/apps/scalable/$n" ]; then
    printf "%-38s %s links\n" "$n" "$(ls "links/apps/scalable/$n" | wc -l)"
  else
    printf "%-38s NO LINKS\n" "$n"
  fi
done
```

`NO LINKS` does **not** mean "safe to delete", nor "broken". It means coverage is
uncertain: the short name works for the native package and for older apps that
still request the icon by that name, but it does not cover anything following the
app ID convention. It may be junk or it may be a good icon left unwired — the steps
below tell the two apart.

## 2. Measure actual usage through Flathub

The app IDs are already in the repo: they are the symlink names in reverse-DNS form.

```bash
# extract the category's app IDs
for f in src/apps/scalable/$CAT/*.svg; do
  n=$(basename "$f" .svg); d="links/apps/scalable/$n"
  [ -d "$d" ] || continue
  for l in "$d"/*; do
    id=$(basename "$l" .svg)
    echo "$id" | grep -qE '^[A-Za-z0-9_]+(\.[A-Za-z0-9_-]+){2,}$' && echo "$n|$id"
  done
done | sort -u > /tmp/ids.txt

# query install counts
while IFS='|' read -r icon id; do
  n=$(curl -s --max-time 15 "https://flathub.org/api/v2/stats/$id" \
      | grep -o '"installs_total":[0-9]*' | cut -d: -f2)
  printf "%12s  %-28s %s\n" "${n:--}" "$icon" "$id"
  sleep 0.3
done < /tmp/ids.txt | sort -rn
```

Icons **without** links have no app ID in the repo — infer it (`org.kde.kdenlive`,
`com.github.wwmm.easyeffects`) and query the same way.

App metadata: `https://flathub.org/api/v2/appstream/<id>` (the `launchable` field
carries the `desktop-id`).

**Limits of the metric.** It only measures Flatpak. It badly underestimates anything
distributed as `.deb`, through the AUR or as an AppImage — especially **music and
professional video production** (Ardour, Hydrogen, REAPER). An empty result means
"not published on Flathub", not "dead app": legacy spellings such as
`org.gnome.cheese` (the published one is `Cheese`) come back empty and are
legitimate defensive aliases.

## 3. Classify

| Category | Signal | Action |
|---|---|---|
| Dead | project shut down or archived — confirm on the web | delete |
| No such app | it is a website or service, never had a Linux client | delete |
| Obsolete version | product absorbed into another | delete |
| Duplicate | same app, two files | consolidate into a symlink |
| Artifact name | `XXXX_Name.0` generated by Wine | move to `_wine-games`, rename |
| Poor name | `natronIcon256_linux`, `mixxx-icon` | `rake apps:rename` |
| Low usage | a few thousand installs | owner's call |
| **No links** | popular app, artwork ready, unwired | **create the symlink** |

Confirm "dead" on the web before deleting. During this audit I got it wrong twice by
guessing from memory: I called BeamNG.drive and CurseForge Windows-only, and both
ship native Linux builds.

## 4. Check the links before deleting

```bash
rake links:aliases -- <name>.svg
ls links/apps/scalable/<name>/
```

- **No links** → deleting the SVG is enough.
- **Has links** → decide whether the link directory goes too. If every alias belongs
  to the same dead app, remove the directory as well; leaving it creates an orphan
  and breaks `test/links/valid_target_test.rb`.
- **Shared artwork** → be careful. `simplescreenrecorder/` hosts byzanz, istanbul,
  xvidcap and others; deleting the SVG would break all of them. Remove only the
  symlink for the app in question.
- Before deleting an alias, check what it points at. `xdman.svg` served **Varia**,
  not XDM; `com.github.vkohaupt.vokoscreenNG.svg` pointed at the artwork of its
  **competitor** SimpleScreenRecorder.

## 5. The inverse problem: popular app with no link

Usually the most valuable finding. In `_media`, 14 unlinked icons added up to over
5 million installs — Kdenlive alone had 1.76 million.

**Flatpak convention:** the icon an app ships is prefixed with its app ID, and that
is the name a modern app is usually looked up by. Hence the repo's convention: SVG
under the short name in `src/` for the native package, app ID as a symlink in
`links/`.

This is **not** an absolute rule, though. A `.desktop` file's `Icon=` key may still
point at a short name, and the GNOME store has old apps that never migrated to the
new naming — there the short name alone works. So creating the app ID alias
**widens** coverage; it does not repair a broken icon. Treat it as an opportunity,
not a bug.

```bash
rake links:aliases -- <icon> --add <app.id>
```

When the file in `src/` is already named after the app ID, the missing piece is the
reverse — an alias under the short name (`amberol.svg`, `kooha.svg`).

## 6. Links pointing at a competitor's artwork

```bash
ruby -e '
def norm(s) = s.downcase.gsub(/[^a-z0-9]/, "")
def toks(n) = n.split(/[.\-_]/).map { |t| norm(t) }.reject { |t| t.length < 4 }
GENERIC = /\A(accessories|application|preferences|multimedia|system|utilities|office|internet|media|audio|video|text|image|folder|user|emblem)-/
Dir.glob("links/apps/scalable/*/*").each do |p|
  next unless File.symlink?(p)
  a = File.basename(p, ".svg"); t = File.basename(File.readlink(p), ".svg")
  next unless a.match?(/\A[A-Za-z0-9_]+(\.[A-Za-z0-9_-]+){2,}\z/)
  next if t.match?(GENERIC)
  na, nt = norm(a), norm(t)
  next if na.include?(nt) || nt.include?(na)
  next if toks(a).any? { |tk| nt.include?(tk) || toks(t).any? { |tt| tt.include?(tk) || tk.include?(tt) } }
  puts "[#{File.basename(File.dirname(p))}]  #{a} -> #{t}"
end'
```

Results come in three kinds, and only the third is a problem:

1. **Same app, renamed** — `im.riot.Riot → element-desktop`. Correct.
2. **Deliberate family** — `discord/` hosting gtkcord4 and WebCord. Correct.
3. **Separately branded competitor** — `de.haeckerfelix.Shortwave → tuner`. Wrong.

For kind 3, rank by install count and record it in `todo.md` rather than drawing on
the spot.

## 7. Wrap up

```bash
rake test      # should leave only the pre-existing failures
git status --short
```

## Traps

**Every symlink in this repo dangles.** They point at the bare filename, resolved at
install time. `find links -xtype l` lists all of them and diagnoses nothing.

**A chained symlink breaks the test suite.** Creating
`avidemux/org.avidemux.Avidemux.svg` failed because `totem/avidemux.svg → totem.svg`
already existed, forming `org.avidemux.Avidemux → avidemux → totem`. `rake
links:aliases --add` now refuses to create such a chain, but when linking by hand,
check whether the icon name already appears as an alias elsewhere:

```bash
find links -name '<icon>.svg'
```

**A hash proves duplication, not distinctness.** An identical `md5sum` means a
literal copy and can safely become a symlink. A different hash only says the artwork
differs — it may still be the same app drawn twice.

**Wine-generated icon names are not publishable.** The hex prefix in
`5C12_World_of_Warcraft_Launcher.0` comes from icon extraction and varies per
machine. Those live in `_wine-games` under a readable name, without links — whoever
installs the app wires it up. Apps run through Steam+Proton do not have this
problem: Steam generates a stable name.
